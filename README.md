# 通信科协 STM32 软件任务二 · 串口控制 PWM 呼吸灯

我用 STM32F103C8 的 TIM2 输出 PWM，通过 USART1 接收上位机的亮度、呼吸开关和周期指令。OLED 显示最近收到的内容和处理结果。这次我从任务一的 GPIO 点灯接着往下做，开始用定时器控制亮暗，并让主循环根据串口命令运行。

## 任务书要求与实现

| 要求 | 我的实现 |
| --- | --- |
| 用定时器输出 PWM 调节 LED 亮度 | TIM2_CH1 从 PA0 输出约 1 kHz 的 PWM，通过 CCR1 调节有效电平时间。 |
| 上位机可以指定 0%～100% 的亮度，步进 1% | 一个 PWM 周期有 100 个计数，输入百分数直接用于设置 CCR1。 |
| 通过串口开启或关闭呼吸 | `Breathing_ON` 和 `Breathing_OFF` 修改 `BreathingFlag`。开启后主循环重复执行渐亮和渐暗。 |
| 呼吸周期可以在 1～5 s 之间设置，步进 1 s | 输入 `1s` 到 `5s`，每一步分别延时 5、10、15、20、25 ms。设置周期也会开启呼吸。 |
| 每条指令应有串口回显 | 上位机收到包含设定值的回包、开关确认或者 `ERROR_COMMAND`，OLED 同时显示接收内容及回复。 |

任务书还要求提交任务报告和演示视频。拍摄亮度变化时可以锁定相机曝光，减少自动曝光对画面的影响。

## 实现与复现

### PWM 参数

在 [PWM 驱动](Hardware/PWM.c) 里，TIM2 输入时钟按 72 MHz 计算，PSC 为 `719`，ARR 为 `99`。计数时钟为 `72 MHz ÷ 720 = 100 kHz`，100 个计数形成 1 个 PWM 周期，输出频率为 1 kHz。PWM1、高电平有效时，占空比为 `CCR1 / (ARR + 1)`，写入 50 就得到 50% 占空比。下面的亮度指令按 LED 高电平点亮接法理解。

呼吸用两个 `for` 循环更新 CCR1，代码依次写入 `0…99` 和 `100…1`。每轮包含 200 次延时，因此目标周期为 `200 × 每步延时`。

| 目标周期 | 1 s | 2 s | 3 s | 4 s | 5 s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 每步延时 | 5 ms | 10 ms | 15 ms | 20 ms | 25 ms |

### 串口指令

在 Keil µVision 打开 [project.uvprojx](project.uvprojx) 并下载。使用 3.3 V 电平的 USB 转串口模块，模块 RX 接 PA9，TX 接 PA10，并与开发板共地。串口参数为 **9600、8N1**。发送 ASCII 文本，包头为 `@`，结尾为 `\r\n`。如果上位机自动附加 CRLF，输入框只需填表里的文本。

| 发送文本 | 行为 | 回复示例 |
| --- | --- | --- |
| `@50%` | 设置 50% 占空比 | `LED_50%` |
| `@Breathing_ON` | 开始呼吸，使用当前周期 | `Breathing_ON_OK` |
| `@Breathing_OFF` | 停止自动更新 CCR1 | `Breathing_OFF_OK` |
| `@3s` | 周期设为约 3 s，并开启呼吸 | `BreathingT_3s` |

要演示固定亮度，先关呼吸，再发 `@0%`、`@50%` 或 `@100%`。当前版本的解析对有效指令可用，百分数和秒数的范围还没有在代码里做完整校验。串口接收和回包在 [Serial.c](Hardware/Serial.c)，指令解析和呼吸循环在 [main.c](User/main.c)。

## 遇到的问题及解决过程

### 调亮度和调呼吸快慢，分别改哪个量

一开始我把两者都理解成“调 CCR”。读代码和计算参数后，我把它们区分开了。CCR1 决定当下的占空比，PSC 和 ARR 决定 PWM 本身的频率。呼吸快慢取决于相邻两次 CCR1 更新之间隔多久。用 1 s 除以 200 个更新步骤，得到每步 5 ms，再依次算出 2～5 s 的步进延时。这样改变呼吸周期时，LED 仍由同一个约 1 kHz PWM 驱动。

### 呼吸只跑一次，加内层无限循环又关不掉

最初我把呼吸逻辑放在接收到串口指令的分支里。去掉内层 `while(1)`，一次开启指令只会跑一轮。加上内层无限循环，主程序又回不到处理关闭指令的位置。即使 USART 中断能被触发，它也只接收数据并设置就绪标志，关闭呼吸仍要靠主循环解析指令。

我加了 `BreathingFlag` 保存开关状态，并把两段渐变循环放在外层主循环中。改完缩进后仍然只执行一次，继续核对右大括号才发现呼吸代码其实还在 `if (Serial_RxFlag == 1)` 里面。最终把串口分支的结束大括号移到 `Serial_RxFlag = 0;` 后面，每轮独立检查 `BreathingFlag`。现在串口分支负责改状态，呼吸分支根据状态运行。

这个版本保留了便于理解的阻塞式渐变。USART 中断可以在呼吸时收到一条新指令，但主循环通常要等本轮结束才执行它。演示时可以等回复再发下一条，周期设得越长，关闭命令可能等得越久。
